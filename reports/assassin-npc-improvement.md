# 暗殺者を使うNPCの比較実験

対象はWeb版 `jinrocard`。本番の「強い」は公開残存札から24の仮想手札を作り、HP、直近最大6夜の履歴、2枚出しの頻度を使って相手の行動を予測する。暗殺者の予想候補は予測での上位2役職。暗殺者を含まない手とも今夜の期待値で比較するが、2枚使うと予想は共通で、調査記録や調査を待つ価値は使わない。前回の実験では翌夜先読みが有望だった一方、調査活用だけで勝率改善を確認できなかった。

## 方式と情報の扱い

| 方式 | 内容 |
|---|---|
| A | 現行の「強い」同士。席とデッキ相性の対照。 |
| 基盤 | 前回の実験用の一夜評価。現行とは乱数消費順やHP・供給の評価に差がある。 |
| B | 基盤に予想改善を追加。48の仮想手札から使用確率を推定し、上位3役職を試す。相手モデルの変化は暗殺者以外の手の評価にも効く。 |
| C | B＋本人の占い師・預言者の情報。 |
| D | B＋使用・温存の判断。 |
| E | B＋調査情報＋使用・温存。 |
| F | E＋前回の翌夜先読み。上位4手、4つの仮想未来だけ再評価。 |
| G | 前回の翌夜先読みのみ。Fとの比較で暗殺者向け変更の追加効果を確認。 |

相手の初期・残存構成と履歴で役職の優先度を補正する。公開HPに応じて魔女・防御・自傷の価値を変え、相手の手札枚数と独裁者による枚数制限を守った仮想手を作る。予想候補の確率は、仮想手札に含まれる頻度ではなく、48の仮想手のうちその役職を実際に出した割合。相手が2枚出せるため、役職ごとの確率の和は1を超え得る。

占い師で見た札は、経過夜数と観測状態によって確率の重みを下げる。預言者で確認した札が山札に残るなら、公開残存枚数からその既知の位置を除外して仮想手札を引く。ドロー済みなら候補の重みを上げる。通常・追加ドロー、墓守の挿入、再構築による位置の更新はエンジンの公開イベントに基づく観測記録を利用する。使用済み・順序不明は根拠から外す。同一役職について記録を単純に足し合わせない。今夜の調査結果は今夜の手決定には使わない。

暗殺者2枚の場合は、上位3候補の同じ予想と異なる予想を含め、最大9通りの組み合わせを個体IDごとに比較する。別の札を組み合わせる手や1枚を残す手も同じ候補集合に入る。温存方式は、推定的中率が低いほど消費に小さなペナルティをつけ、暗殺者を残しながら調査を行う手に加点する。残り夜数が少ない、自分が低HP、手札上限に近い場合は温存の重みを下げる。致死・第15夜の勝敗は通常の評価に含まれる。

実験NPCには読み取り専用型の公開スナップショットと本人に許可された調査記録だけを渡す。相手の非公開手札・山札順・今夜の伏せカード・相手限定の調査・相手のカード個体IDを渡さない。TypeScriptのルール計算と乱数だけで動作する。生成AI、学習済みモデル、外部サービス、プレイ時の通信は使用しない。

## 実験条件

実戦は正式な `Duel` で解決し、選択が合法か毎回検証。HP20、デッキ20枚、15夜、手札上限7、夜末の手札補充2、暗殺者は特殊4ダメージで採用上限2枚。共有者などの追加選択方針は方式間で共通。ゲームとNPC乱数は独立させ、席を入れ替え、各方式で同じ出発シードを使った。行動が分岐した後のドローは一致するとは限らない。

1枚型は標準の占い師を道化師に、2枚型はさらに独裁者を暗殺者に交換。占い師型・預言者型は2枚型の道化師を各調査役職に変更。両方型は占い師型の呪術師を預言者に交換した。速攻・耐久・情報・コンボは共通生成器の固定シード、D343は以前の探索報告の20枚。ランダムの相手は対戦ペアごとに生成。実験側はすべて暗殺者を採用したデッキ。

予備は方式あたり100試合（5シード×10組み合わせ×両席）、合計800試合。最終は未使用シードで方式あたり900試合（45シード×10組み合わせ×両席）、合計7,200試合。総計8,000試合。引き分けを含む全試合を勝率の分母とする。95%区間は席交換ペアを1標本とし、対戦組み合わせ別の分散を使う正規近似。方式間の勝率差は同じシード・席ペアの差に基づく。区間は多重比較を補正していない。

```powershell
node --experimental-strip-types scripts/assassin-npc-improvement.ts pilot 5
node --experimental-strip-types scripts/assassin-npc-improvement.ts final 45
npm test
npm run build
```

## 結論
